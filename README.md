# Smart Drone Delivery

A simulated delivery drone on an 8x8 grid. The map is given as an image, a small CNN reads each cell, and a search algorithm plans a route that visits every delivery point and returns to base. A Pygame window shows the route and the drone flying it.

I built it as a university project at the University of Perugia, to practise image classification and classical search on the same problem.

## The problem

Each cell is one of five types:

| Symbol | Cell | Cost to enter |
| --- | --- | --- |
| `S` | Start / base | 1 |
| `D` | Delivery point | 1 |
| `W` | Wind | 2 |
| `X` | No-fly zone | not allowed |
| `E` | Empty | 1 |

The drone moves up, down, left or right. A search state is the drone's position plus the set of deliveries still pending (a `frozenset`, so two paths that reach the same cell with the same deliveries left count as the same state). The goal is no pending deliveries and the drone back on `S`. The heuristic for A* and the other informed searches is Manhattan distance.

## Reading the map: CNN

`image_parser.py` cuts the map image into 28x28 grayscale cells and classifies each one with a CNN written in PyTorch:

```
1x28x28 → Conv(16) → ReLU → MaxPool → Conv(32) → ReLU → MaxPool → Linear(128) → Linear(5)
```

The training set is generated by the code itself: 1,000 images per class with small rotations and Gaussian noise, split 80/20, trained with Adam and cross-entropy. The trained weights are in `cnn_model.pt`, so the app runs without retraining.

On the 1,000 held-out test images the saved model classifies every cell correctly (100% accuracy). That says more about the data than the network: the symbols are generated letters with mild noise, so a real map photo would be a much harder test.

## Planning the route

`controller.py` implements nine search algorithms. These are the results on `test_map_2.png` (26-step route):

| Algorithm | Steps | Cost | Nodes expanded | Time |
| --- | ---: | ---: | ---: | ---: |
| BFS | 26 | 28 | 236 | 6 ms |
| DFS | 82 | 85 | 100 | 4 ms |
| IDS | 26 | 28 | 8,880 | 205 ms |
| UCS | 26 | **26** | 236 | 14 ms |
| Greedy best-first | 26 | 27 | 69 | 3 ms |
| A* | 26 | **26** | 247 | 12 ms |
| IDA* | 26 | **26** | 1,067,724 | 32 s |
| RBFS | — | — | — | over 60 s |
| SMA* | 26 | **26** | 4,202 | 242 ms |

BFS and IDS find the fewest steps but ignore wind, so their routes cost more. UCS, A*, IDA* and SMA* find the cheapest route, and A* does it while expanding about as many nodes as BFS. IDA* and RBFS keep no memory of visited states, so on this map they revisit the same states over and over. For that reason they are left out of the automatic comparison (key `C`), though you can still run them one at a time.

## Running it

Python 3.10 or newer:

```bash
python -m venv venv
venv\Scripts\activate          # Windows
source venv/bin/activate       # Linux / macOS
pip install -r requirements.txt

python main.py                  # uses the built-in example map
python main.py test_map_3.png   # or loads a map image
```

To regenerate the dataset and retrain the CNN:

```bash
python ml_classifier.py
```

### Controls

| Key | Action |
| --- | --- |
| `1`–`9` | BFS, DFS, IDS, UCS, Greedy, A*, IDA*, RBFS, SMA* |
| `C` | Compare the enabled algorithms |
| `M` | New random map |
| `Space` | Pause / resume |
| `+` / `-` | Animation speed |
| `R` | Reset |
| `Esc` / `Q` | Quit |

## Files

| File | Contents |
| --- | --- |
| `main.py` | Pygame interface and main loop |
| `controller.py` | Search state, the nine algorithms, comparison |
| `environment.py` | Grid, cell types and costs |
| `movement.py` | Move validation and execution |
| `sensors.py` | Simulated position, step and wind sensors |
| `image_parser.py` | Map image → grid, random map generator |
| `ml_classifier.py` | CNN, dataset generation, training |
| `dataset/` | 5,000 generated training images |
